# codex-plan-ledger 重新设计说明

状态：设计稿，供落地改仓。不写最终站点代码。
参考气质：Claude / Anthropic 官网与文档站的暖色、留白、少装饰；结构参考 Plexus README 的 plain / dense / readable，不是 SaaS 营销落地页。

---

## 1. 信息架构

### 官网（`docs/index.html`，GitHub Pages）

自上而下，单页：

1. 顶栏：项目名 · 锚点（用法 / 实测 / GitHub）· 中英切换
2. 首屏：一行状态 · 标语 · 两句说明 · 安装命令 · 两个链接（演示 / GitHub）
3. 怎么用：3–4 步，等宽编号，短句
4. 决策页：一张真实截图 + 三句能力说明
5. 范围偏离检查：说明 + 已知局限灰框
6. 实测：诚实表格 + 一句话结论（轮数没赢；范围偏离 3/3；文件内矛盾 0/3）
7. 页脚：GitHub · MIT · 一行致谢

不做：居中英雄大图、双列卖点彩虹卡、假数据仪表、滚动炫技。

### README（`README.md` / `README.en.md`）

结构对齐官网，但更 dense、以命令和表格为主：

1. 顶栏语言切换链接
2. 标题 + 一行标语（左对齐，不居中堆叠）
3. 链接行 + 安装一行代码
4. 状态引用块（早期原型 + 实测一句话）
5. 它是什么（组件表）
6. 工作流程（mermaid，可保留）
7. 安装 / 用法 / 账本格式 / 范围偏离检查
8. 现在能用的 / 实验性的
9. 实测（完整表格，链到 bench）
10. 状态 / 开发 / 致谢 / 许可

截图：最多 2 张（决策页 1 张 + 流程或 PR diff 1 张）。故事向 GIF、双 GIF 叠放删掉或收到折叠细节里，默认不占首屏。

## 2. 文案语气

- 平实短句，具体动词（写进、对照、报出、抓到）。
- 先讲做什么、怎么用、测了什么；口号放最后或不放。
- 不用「赋能」「革命性」「智能」「一站式」「轻松搞定」。
- 不用破折号堆砌排比；中文不夹无必要英文（专有名词 `/plan`、`decisions.json`、`Stop hook` 除外）。
- 实测必须写清：样本量、赢/平/输、已知局限。不写「省 token」「少轮」。
- 不评价、不贬低其他项目；致谢最多一行中性句。

标语（硬约束，不可改口）：

- 中文：Codex `/plan` 的决策账本
- English: A decision ledger for Codex `/plan`

做法（硬约束）：

把 Codex 问过的问题、未定选项、计划默认做法写入仓库 `decisions.json`，可在 PR 里 diff；写完代码再查范围是否超出计划（范围偏离检查）。

## 3. 色彩与字体（Claude 暖色系统）

冷灰科技蓝、蓝紫霓虹一律不用。背景偏象牙，正文偏深棕近黑，强调色用陶土橙。

### 浅色（默认，官网与 SVG 图）

| 角色 | Hex | 用途 |
| --- | --- | --- |
| 背景 | `#FAF6F1` | 页面底色（象牙 / 暖白） |
| 背景次级 | `#F3EDE4` | 交替区块、表头 |
| 卡片 / 代码底 | `#FFFCF8` / `#F0EBE3` | 卡片、`<code>`、安装条 |
| 正文 | `#1C1917` | 近黑深棕，主文字 |
| 次要文字 | `#78716C` | 说明、图注、页脚 |
| 分隔线 | `#E7E0D6` | border、表线 |
| 强调色 | `#D97757` | 链接、主按钮、进度点（陶土橙 / Claude 感） |
| 强调色文字 | `#FFFCF8` | 强调按钮上的字 |

| --- | --- |

| 背景次级 | `#292524` |
| 卡片 | `#292524` |
| 正文 | `#FAF6F1` |
| 次要 | `#A8A29E` |
| 分隔线 | `#44403C` |
| 强调色 | `#E8956F` |
| 强调浅底 | `#3D2A22` |
| 警示底 / 字 | `#3D2E16` / `#E8C07A` |

### 字体

- 正文 / 标题：系统 UI 无衬线栈（可读、中英混排稳）  
  `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif`
- 可选标题层级：若落地页要更接近 Claude 文档感，`h1`/`h2` 可用  
  `"Iowan Old Style", "Palatino Linotype", Palatino, "Songti SC", "Noto Serif SC", Georgia, serif`  
  字重 600；正文仍用无衬线。两套不要混进同一段。
- 代码 / 命令：  
  `ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace`，14px 左右。

### 字号与留白

- 正文 16–17px，行高 1.65–1.7。
- `h1`：clamp(28px, 4vw, 40px)，字距略紧（-0.02em），**左对齐**，不要 50px 居中英雄标题。
- `h2`：22–28px。
- 区块上下 padding：官网 48–64px；手机 32–40px。
- 内容最大宽：官网 720–800px（正文栏）；表格 / 截图可到 880px。比现在的 1040px 更窄，更像文档。

### 控件

- 主按钮：实心 `#D97757`，圆角 8px，无阴影或极轻 `0 1px 2px rgba(28,25,23,.06)`。
- 次按钮：描边同色，底透明。
- 不要玻璃拟态、backdrop-filter 大面积模糊、渐变填充、霓虹描边。
- 顶栏：实色暖白底 + 1px `#E7E0D6` 底边即可；不要 sticky 毛玻璃。

## 4. 去 AI 味清单

### 禁止

1. 渐变彩虹、霓虹、玻璃拟态堆叠
2. emoji 墙、✨、🚀、「赋能」「革命性」「颠覆」「一站式」
3. 空洞 slogan（如「让计划更智能」）
4. badge 过多（最多 CI + License，合计 ≤ 3；Plexus 式五六枚徽章不要照搬）
5. 居中大标题 + 英雄大图套路
6. 紫 / 蓝紫科技风、冷灰蓝默认（现站 `--acc:#0b6bcb` 必须换掉）
7. 假数据仪表、未标注的「示意数字」
8. 故事向营销短片默认占首屏（可链到 assets，不自动大图循环）
9. 双 GIF / 双视频叠在 README 顶部

### 要求

1. 像认真写的工具文档：层级清楚、留白够、字重克制
2. 正文先讲怎么用、测了什么
3. 截图 / 流程图只用仓库真实资产；没有真实 PR 截图时，保留现有 `ledger-pr-diff.svg` 并标明「示例 / 仓库生成」，不造假数据
4. 实测数字与 `bench/results/` 一致，并写「方向性，不是效果证据」
5. 范围偏离检查对外只叫这个名字；已知局限固定出现
6. 中英切换可见、无障碍（键盘、对比度 ≥ 4.5:1）

## 5. 中英切换

### README

顶部第一行（或标题下第一行），纯 Markdown 链接，无 JS：

```markdown
[简体中文](./README.md) · [English](./README.en.md)
```

当前语言加粗或标为纯文本、另一语言为链接（与现有 Plexus / 本仓习惯一致）。

### 官网

优先无 JS 依赖：

- **推荐**：两个静态页 `docs/index.html`（中文默认或按 Pages 主页）+ `docs/index.en.html`，顶栏互相链；或 `docs/zh/index.html` + `docs/en/index.html`。
- **可接受**：单文件 `?lang=zh|en` + 少量 JS 切换（现状），但默认语言检测不要强行盖过 `?lang=`；localStorage 可选。
- 切换控件：文字链「中文 · English」，不要胶囊大按钮炫技。
- 演示 iframe 随语言换 `demo/plan-zh.html` / `demo/plan-en.html`。

## 6. 空态与缺资产

| 情况 | 写法 |
| --- | --- |
| 无真实 Codex 会话截图 | 用现有无头 Chrome 截图，图注写明「合成样例 fixture + 无头 Chrome」 |
| 无真实 PR diff 截图 | 用 `ledger-pr-diff.svg`，图注「示例，仓库脚本生成，非某次真实 PR」 |
| 实测未跑 / 样本不够判定线 | 只写「方向性，n = 3；未达测量计划的重复次数」；数字栏不留空承诺 |
| 演示页未生成 | 链到 `plan-ledger render` 命令，不放空白框 |
| 故事 GIF 不作为默认首屏 | README / 官网首屏不嵌入；需要时放在「演示素材」小节或 assets 目录说明 |

## 7. 对现有 README / 官网的问题清单

### 视觉与版式

1. 官网强调色 `#0b6bcb`（冷蓝）+ 灰白底，偏通用 SaaS，不像 Claude 暖文档。
2. 首屏 `text-align:center` + clamp 到 50px 的大标题，是典型营销英雄区。
3. sticky 顶栏 `backdrop-filter: blur` 偏玻璃拟态。
4. 卡片圆角 + 双层阴影 + 四列 steps 卡片，装饰多于信息。
5. README 顶部居中 `<h1 align="center">` + 多段居中 + 双 GIF（flow + story）叠放，首屏噪音大、AI 演示感重。
6. 内容栏 1040px 偏宽，长句可读性一般。

### 内容与诚实性（方向对，结构可收）

7. 实测结论与仓库一致（见下节），表述已诚实；但表格和长段同时出现在 README 与官网，可官网留摘要表、README 留全表。
8. 「故事向」GIF 与「流程」GIF 重复讲同一路径，保留一个即可。
9. 致谢两行项目可收成一行中性致谢（军师要求最多一行）。
10. badge / 元信息行（Codex CLI · Node · 零依赖）可保留一行文字，不必做成盾牌墙。

### 与产品定位一致处（保留）

- 标语与「决策账本 + 范围偏离」定位正确。
- 明确写了轮数没改善、不以省轮为目标。
- 已知局限（不读计划内文件内容）有写。
- 不评价竞品。

## 8. 实测数据核对（以仓库为准）

来源：`bench/results/2026-10-09-round1/summary.md`、`round2/summary.md`、`docs/measurement-plan.md`、现行 README。

| 项 | 军师口述 | 仓库 | 结论 |
| --- | --- | --- | --- |
| 配对数量 | 3 对 | 第 1 轮 1 对 + 第 2 轮 2 对 = 3 对 | 一致 |
| 轮数 | 没变少 | 输 2、平 1；没有任何一对 ledger 轮数更少 | 一致 |

## 9. 落地优先级（给改仓同学）

1. 换色与字体变量（去蓝，上暖象牙 + 陶土橙）；顶栏去掉 blur。
2. 首屏改左对齐文档式；删 README 双 GIF 叠放，只留一张决策页图 + 可选一张流程/diff。
3. 粘贴 `copy-zh.md` / `copy-en.md` 对应区块；致谢收一行。
4. 官网实测区保留摘要表 + 链到 bench；完整方法放 measurement-plan。
5. 中英：README 链接切换；官网优先静态双页或保留 `?lang=` 但样式按本说明收束。
